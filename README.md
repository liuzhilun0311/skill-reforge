# 技能重铸 (skill-reforge)

英文调用标识是 `$skill-reforge`，界面显示为“技能重铸 (skill-reforge)”。

`skill-reforge` 用于分析、整理、迁移和改进已有技能。输入一个技能目录，
输出一个结构清楚的技能，以及有证据支持的对比报告和改进建议。

它会检查用途、流程、输入输出、默认参数、依赖、配置、异常处理和约束，
再按实际用途组织文件。重构默认保持行为；修复和增强会单独说明。

## 使用前准备

- 一个能读取本技能 `SKILL.md` 和本地文件的技能宿主。
- 如需辅助盘点、基线副本与产物比较，安装 Python 3.10 或更高版本；三脚本仅用标准库。
- 准备来源技能和可用测试输入。实际运行来源可能另需依赖、账号或工具。
- 分享代码或素材前，确认使用与分发权限；必要法律声明随成果保留。

本技能不保证任意技能自动转换成功，也不保证第三方服务在本地可运行。
不需要 API Key 就能执行本技能自带的静态盘点与本地文件比较。

## 安装与调用

将整个 `skill-reforge` 文件夹放入目标宿主支持的技能目录，按宿主说明刷新技能。
不要只复制 `SKILL.md`，它会引用同目录的资料与脚本。
开发期间，也可以直接让助手读取此目录下的 `SKILL.md`。

```text
使用 $skill-reforge 分析 ./input/report-skill，
重构为 ./output/report-builder。
保持原有输入和输出格式，检查个人路径与配置，
对两版执行相同用例，并给出问题清单和改进建议。
```

先分析、不修改：

```text
使用 $skill-reforge 分析 ./input/report-skill，
只提交能力契约、文件映射、问题清单和测试方案，暂不创建目标技能。
```

仅检查已重构结果：

```text
使用 $skill-reforge 对比 ./input/report-skill 与 ./output/report-builder，
检查输入兼容、失败处理和输出结果；将无法实际验证的部分单列。
```

## 配置

`config/settings.json` 影响静态盘点及基线副本的文件选择；重构的业务决策
由用户要求与能力契约决定。

| 配置键 | 用途 |
| --- | --- |
| `exclude_dirs` | 不盘点、不复制的目录名称；跳过项仍出现在报告中 |
| `max_text_bytes` | 对单个普通文本文件执行静态标记扫描的字节上限 |
| `sensitive_names` | 不读取正文、不复制的敏感文件名，大小写不敏感 |

默认配置中的值是唯一默认值来源。配置缺失、键名错误或非法值会明确报错；
不要把密码或访问令牌写入这份配置。
新增的来源专用排除项应说明原因，不能据此声称相关内容已经分析。
排除运行必需的依赖或配置可能使基线无法执行；扫描字节上限只限制文本分析，
不限制普通非敏感文件的复制。

## 辅助命令

从本技能根目录运行，路径有空格时加引号：

```text
python scripts/inspect_skill.py "../source-skill"
python scripts/inspect_skill.py "../source-skill" --config config/settings.json
python scripts/prepare_baseline.py "../source-skill" "../work/new-baseline"
python scripts/compare_runs.py "../work/baseline/run.json" "../work/target/run.json" --plan "../work/plan.json"
python -B -m unittest discover -s tests -v
```

盘点命令不执行来源代码；JSON 输出不包含文本片段或密钥原文，但相对文件名、
大小和行号也可能有敏感性，分享报告前应检查。退出码：
0 表示完成可执行范围的盘点，1 表示读取错误或无法完成扫描，2 表示输入配置错误。
即使退出 0，也须查看 `complete` 和 `skipped`；有意排除的内容不算已检查。

基线副本命令要求目标容器尚不存在、其父目录已存在，且与来源互不包含。
成功生成 `source/` 和 `snapshot.json` 后，基线程序仅在副本运行。
它保留空目录和二进制资源，不复制已排除目录或敏感配置文件；
退出 0 表示完整复制，1 表示存在排除项，2 表示失败。副本是否能运行仍需检查。
`scan_complete` 仅描述文本扫描范围，和复制完整性 `complete` 含义不同。
失败时可能留下部分副本，没有有效 snapshot.json 就不可用于测试。
失败 JSON 保留 `error: snapshot_failed`，并提供 `reason` 和 `partial_copy`，
区分配置非法、来源无效、目标已存在、父目录无效、链接、来源变化及权限问题。
`partial_copy` 表示本次已创建但未成功完成的容器；不会清理或覆盖已有目标。
该工具不执行来源代码，也不是安全沙箱；绝对路径写入、联网和外部副作用需另行审查。

比较器要求先运行两个版本，记录格式见
[验证协议](references/validation.md)。退出码：
0 表示记录和指定产物相符，1 表示差异或阻塞，2 表示记录或路径不合法。
版本 2 必须提供实施前固定的用例计划，检测两边同时漏测、计划不符及执行失败。
函数和模型任务不填写进程退出码；全部不适用也不会返回成功。
旧版记录仍可比较，无计划时结果范围为 `recorded_cases_only`，不能据此证明覆盖完整。
它不会替你执行来源技能，不会证明手写记录真实或计划确实在实施前固定。

## 结果与问题处理

正常交付包括目标技能目录、对比测试证据，以及目录外的工作报告。
重要脚本修复应附可独立运行的最小离线回归测试及命令；测试源码与合成输入
可以随技能分享，运行日志和产物保留在目录外。
报告区分原有问题、已实施修复、可选优化和未验证事项；不会把离线桩测试写成
真实服务验证，也不会把无法运行的用例记为通过。
分享前对实际目标和分发包执行[最终检查](references/release.md)。
报告分别说明技术验证与分享状态：仅分析、本地草稿、分发待确认或分享检查通过。
本地重构完成不代表分发依据已经确认，也不默认安装、打包或发布。
模型能力评测与工具测试分开，方法见[行为评测](references/behavioral-evaluation.md)。

- 来源目录不完整：补齐实际引用文件，或接受明确标出的覆盖缺口。
- 缺依赖或密钥：先完成静态分析与可执行部分，保留真实运行阻塞项。
- 两版输出不同：先判断是回归、非确定性还是获准行为改变，再确定验证方法。
- 无配置的目标技能：`config/` 可以为空；Git 分发时可使用 `.gitkeep`。

个人路径、无关账号和推广可清理；运行必需服务地址及法律要求保留的声明不能
一概删除。文档使用直接的产品说明口吻，不附加虚构作者或原创经历。
