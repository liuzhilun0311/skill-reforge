# 能力分析与信息分类

## 建立能力契约

每项能力记录以下字段；没有证据时标记未知，不能凭经验补成既有行为。

| 字段 | 要回答的问题 |
| --- | --- |
| 触发与排除 | 哪类请求应触发？相近请求中哪些不应触发？ |
| 输入 | 路径、格式、编码、大小、必填项、默认值、环境变量是什么？ |
| 流程 | 入口如何选择分支？脚本、提示词、资料和外部工具如何配合？ |
| 输出 | 文件、命名、编码、结构、展示方式、状态码和副作用是什么？ |
| 依赖 | 运行时、包版本、系统工具、服务端点、密钥、权限是什么？ |
| 约束 | 隐私、成本、授权、网络、平台和许可证限制是什么？ |
| 失败处理 | 超时、重试、缺依赖、非法输入和部分完成如何表现？ |
| 证据 | 哪段文档、代码或真实运行支持上述结论？ |

从 `SKILL.md` 的引用向下追踪，也从脚本的 imports、文件打开、配置读取、
subprocess、网络调用和输出写入反向核对。不能只读入口和 README。
样例文件、隐藏配置、二进制模板、字体、嵌套包、动态拼接的路径也要检查。

对较大的技能先建立文件依赖图，然后按调用关系阅读。盘点脚本只做粗分类：
自定义目录和文件名可能误分类，需要人工修正。其静态标记不会识别所有个人信息，
也不保证发现所有密钥。

## 分类决定，避免盲目替换

| 类型 | 处理原则 |
| --- | --- |
| 本机用户名、绝对路径 | 用实际可配置或相对定位替代，验证跨目录运行 |
| 真实密钥、令牌、个人账号 | 不复制值；接入安全配置方式，文档使用明确示例 |
| 无关推广、社交链接、作者介绍 | 可以从产品说明中删除 |
| 必需 API 域名、模型名、工具 ID | 保留或提供可用适配；替换后必须验证 |
| 文件名、导入名、配置键中的品牌 | 先查调用者，确认兼容方案再改 |
| 许可证、版权、NOTICE、署名 | 依据具体条件保留；不确定时报告而非删除 |
| 图片、字体、样例数据 | 分别核查权利与功能用途，不因改目录就视为自有 |
| 无法读出的二进制或动态依赖 | 标记未审查，使用相应工具或请求必要材料 |

来源名出现在某处，并不自动意味着它应删除。隐去身份也不产生代码或素材的
使用权。不要虚构“已经取得授权”或提供法律结论；只记录可获得的文件与事实。
没有清晰分发依据时，仍可完成分析和独立设计。用户已要求本地重构时，
不因未发现许可证就自动中止本地工作，也不据此推断可分发；已有明确使用限制
须遵循，必要时只输出方案。复用实现及素材的待确认依据写入内部报告，
按 [交付状态](release.md#交付状态) 标注，不打包、发布或宣称已取得分享许可。

## 问题与建议

每条问题包含：具体证据、触发条件、实际影响、严重程度、建议、兼容成本、
验证方法及实施状态。

- 严重：数据泄露或破坏、越权副作用、错误结果、无法启动。
- 中等：平台限制、缺依赖说明、脆弱路径、配置失效、未处理错误。
- 轻微：文档重复、难维护、命名模糊、无用资源。

以上是排序参考，不把没有证据的风险写成已存在漏洞。
优先处理可复现问题，再考虑减少重复、降低耦合、改善配置和测试。
说明优化收益与代价，不为展示“深度”引入新依赖或重写稳定组件。

每次迁移给出覆盖表：

```text
能力 | 来源证据 | 目标实现 | 基线用例 | 目标用例 | 结论/缺口
```

若无法获得源码，只能分析可见的说明和观察到的行为，明确置信范围，
不得声称已理解隐藏实现。
