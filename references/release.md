# 分享前检查

对实际目标目录执行，而不只检查来源或入口文档。
已明确不制作分发包时，只完成目录检查并说明未检查包。

## 交付状态

执行范围、技术验证和分享状态分别记录。根据事实选择当前分享状态，
不因测试通过或文件改名自动升级：

| 状态 | 适用条件及可交付内容 |
| --- | --- |
| 仅分析 | 交付能力契约、设计与建议，不创建目标实现 |
| 本地草稿 | 用户要求本地重构，已有目标；尚未要求或完成分享验收 |
| 分发待确认 | 有分享目标，但复用依据、必要声明或必需技术检查仍有阻塞；列出解除条件 |
| 分享检查通过 | 声明的支持范围内必需检查通过，已记录复用与分发依据，必要声明随成果保留 |

未发现整体许可证不等于获得分发许可，也不单凭这一事实断定不能本地修改。
已有明确限制按其条件处理；依据未知时可以在现有授权范围内分析和制作本地草稿，
不得把尚未确认的复用实现或素材作为已获准成果打包、发布。
分享检查通过仅描述已核对的事实和范围，不构成法律结论或自动发布授权。
不能检查包时说明只完成目录检查；不要求为取得更高状态额外调用付费服务。

## 目录与信息

1. 列出交付文件，确认包含入口、README、中文元数据、config 及实际依赖。
   检查所有链接、导入、脚本路径、模板定位和默认提示词调用名。
2. 对目标再次执行 `inspect_skill.py`。逐项处理 findings、skipped 和 errors。
   关键文件未审查时不能声称全面检查。二进制素材的可见内容和元数据按需
   用相应工具检查，无法检查时记录范围。
3. 核对分析阶段发现的具体个人路径、账号、联系方式和推广是否按决定处理。
   不把来源名作为全局禁词；法律声明和必需运行标识可保留并说明理由。
4. 检查真实密钥、访问令牌、运行日志、绝对个人路径、缓存、内部报告和测试产物。
   配置示例使用明确占位值，原有真实秘密不进入示例、快照或分享包。
5. 核对必须保留的 LICENSE、NOTICE、源码头和修改说明确实随包提供，
   不把移至内部报告视为保留。
6. 对照运行前提与兼容验收表，核对新增平台、文件系统、配置、网络等要求，
   README 中的适用范围与实际证据一致。
7. 重要脚本修复的最小回归测试在目标内可用，说明运行命令；检查其不依赖
   来源路径、内部工作区或真实秘密。无法提供时记录具体缺口。

测试代码中的合成地址、文档中的参数名等标记可能合理。记录分类与理由，
不自动删除所有邮箱、域名或 credential_reference，也不保证来源不可识别。

## 分发包

- 从明确文件清单打包，不直接压缩包含真实配置和日志的工作目录。
- 列举实际包条目，拒绝绝对路径、`..`、意外链接及越界资源。
- 确认空 config 按分享方式保留，Git 可用 `.gitkeep`。
- 核对包内文件集合与交付目录清单一致，各文件摘要一致，校验归档完整性。
- 解压到新目录，运行适用的结构校验和测试，确认没有依赖工作区外的文件。
- 保存最终包摘要、检查结论和未覆盖范围；工作报告留在分发目录外。

摘要一致只证明打包内容一致，不能替代信息检查、运行测试或权利判断。
