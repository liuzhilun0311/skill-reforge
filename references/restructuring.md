# 目录与文档重构

## 面向读者分工

| 位置 | 内容 | 不应重复放置的内容 |
| --- | --- | --- |
| README.md | 用途、前提、安装、配置入口、调用示例、常见问题 | 完整模型决策流程 |
| SKILL.md | 触发、输入处理、流程、约束、检查、交付及资料入口 | 安装教程和所有参数手册 |
| agents/openai.yaml | 中文显示名、简介、含实际调用名的默认提示词 | 业务配置与执行流程 |
| config/ | 脚本真正读取的配置、无密钥示例 | 模板、文档和运行日志 |
| scripts/ | 可执行辅助逻辑 | 只有说明没有代码的文件 |
| references/ | 按需读取的规则、协议、参数解释 | 配置值的重复副本 |
| assets/ | 生成结果所需模板、图片、字体 | 执行日志和审计报告 |

可以有 tests、schemas、packages 或根目录 LICENSE/NOTICE。
依赖包布局、构建入口、包资源路径确有要求时保留，不强行搬进 scripts。
不生成与用途无关的空目录。基础 config 无文件时可以为空。

## 重构顺序

1. 列出“来源文件 -> 目标文件 -> 调用方 -> 更新点 -> 验证方法”。
2. 从契约编写新文档，保留精确协议、参数语义和必要约束。
3. 迁移实现与资源，修正所有调用方；不要用全局字符串替换处理名称。
4. 按脚本自身位置或明确项目根定位资源，不依赖操作者的当前工作目录。
5. 配置默认值只维护一处。实际运行值、示例值与文档说明明确区分。
6. 验证 imports、相对链接、命令示例、工具依赖和资源引用。
7. 从非项目当前目录执行入口，验证含空格、中文和不同输出目录的路径。

README 和 SKILL 的少量用途介绍可以相似；核心流程、参数表与规则不各维护一份。
SKILL 必须能独立指导执行，不能要求模型先通读 README 才知道工作方法。

## 名称和元数据

目标目录名与 frontmatter 的 name 一致，使用小写英文、数字和连字符，
不默认加个人前缀。description 说明能力及触发条件，不堆积泛化关键词。

界面示例：

```yaml
interface:
  display_name: "报告生成"
  short_description: "根据数据生成结构清晰的月报和经营分析，支持模板与结果检查"
  default_prompt: "使用 $report-builder 根据提供的数据生成报告。"
```

实际名称不同则同步修改提示词。保留仍有效的 policy 和 dependencies，
不因重写界面文件静默移除工具要求或改变调用策略。

## 写法与来源信息

产品文档直接说明“输入什么、如何执行、输出什么”，不需处处叙述迁移过程。
技能需要第一人称时，可以写“我先验证输入，再生成结果”，不要写虚构经历、
“全部独立原创”或伪造作者身份。

工作报告保留来源依据、文件映射和测试差异，供维护者核对；
公开包不默认包含内部日志和工作报告。依法需要的来源或修改声明应放在
适当的 LICENSE、NOTICE、源码头或说明中，不能转移到不随包分发的位置。

## 文档排版

适用于重构时新建或修改的 SKILL.md、README.md、参考文档和 Markdown 模板。

- 一句话或一条完整规则一行，不为凑固定长度或行宽在句中强行断句；长行交由编辑器自动折行显示。
- 同一主题的句子可逐句换行，保持在同一段落；不同主题之间空一行。
- 列表中的一条完整规则保持在同一行；需要多个独立步骤时拆成多个列表项。
- 保留代码块、命令、表格、YAML 等结构所需的换行和缩进，不将正文排版约定套用到结构化内容。
- 整理已有文档时，只合并因行宽产生的续行，保留标题、段落、列表层级及有语义的 Markdown 硬换行。

## 行为改变

分为三类记录：

- 保持：接口与可观察行为不变，结构和表述整理。
- 修复：已确认问题的获准修改，描述旧行为、新行为和回归测试。
- 增强：新能力、依赖或交互方式，说明收益、兼容性与成本。

不把修复或增强悄悄纳入“完全等价”结论。需要保持旧接口时可提供兼容入口，
不为了删除旧名字而破坏调用者。

## 运行前提与兼容验收

每项修复或增强核对适用项；相同项可合并说明，不适用项标明理由。

| 维度 | 应核对的前后差异 |
| --- | --- |
| 运行时与包 | 最低版本、系统工具、新增包及其可用性 |
| 平台与文件系统 | OS、权限、大小写、硬链接/原子写入支持、跨卷和网络目录 |
| 配置与启动 | 必需文件、默认值、环境变量优先级、旧配置能否继续启动 |
| 网络与副作用 | 新增请求、上传、自动下载、计费或权限要求 |
| 输入输出契约 | 参数边界、路径、命名、字段、错误码、覆盖及失败残留 |

新增前提时先考虑维持原支持范围的实现或明确回退；不能保持时说明范围收窄、
授权依据和用户可见失败行为。增加针对性验证，注明真实环境实测还是故障注入；
仅在一种平台通过，不宣称其他平台或最低运行时已通过。
不要为填充 config 制造配置文件；确有配置需求时保留合理默认与已有接口兼容，
如果改为必需文件，必须把这一变化列入验收。

## 随成果交付的回归测试

修改重要运行代码时，在目标保留或新增能复现缺陷并验证修复的最小测试；
按维护成本选择 tests 或现有测试入口，不强制某种框架。
使用合成输入、临时输出目录和可控离线依赖，不需要来源目录、内部报告、
真实密钥或付费调用。从移位后的目标目录按 README 命令运行，验证独立性。

测试源码与必要合成输入可以分享；日志、缓存、截图等运行产物默认不随包提供。
内部成对比较可以继续放工作区，不要求把来源实现一起带入目标。
纯文档整理不强制造测试；确实无法提供重要修复回归时，说明具体原因及对维护的影响。
